# E2E-тесты: план покрытия

Приоритет — основной сценарий и устойчивость к ошибкам, как в критериях оценки.

## Высокий приоритет

1. ✅ Успешная покупка картой (`catalog-to-order.spec.ts`)
   - Каталог → корзина → чекаут → карта success → страница успеха.

2. ✅ Отказ карты и повтор (`declined-card-retry.spec.ts`)
   - decline → сообщение об ошибке → success → успех.

3. ✅ Отмена платежа и повтор (`cancelled-payment-retry.spec.ts`)
   - cancel → сообщение об ошибке → success → успех.

4. ✅ Наличные при получении (`cash-on-delivery.spec.ts`)
   - Каталог → корзина → чекаут → способ оплата "Наличными" → подтверждение без карты.
   - Проверить, что на странице успеха статус "Заказ оформлен, оплата при получении".

5. ✅ Управление количеством из каталога (`quantity-management.spec.ts`)
   - Добавить товар, увеличить количество, уменьшить до 0 (карточка возвращается в кнопку "В корзину").
   - Проверить, что `+` блокируется на остатке.

## Средний приоритет

6. ✅ Пустая корзина (`empty-cart.spec.ts`)
   - Открыть `/cart` → сообщение "Корзина пуста" и ссылка в каталог.

7. ✅ Товар без остатка (`out-of-stock.spec.ts`)
   - `clock-dot` (stock 0) имеет отключенную кнопку "В корзину".

8. ✅ Валидация формы чекаута (`checkout-validation.spec.ts`)
   - Пустые/невалидные поля (`Имя`, `Email`, `Телефон`) показывают ошибки.
   - Кнопка "Рассчитать стоимость" не отправляет форму с ошибками.

9. ✅ Удаление позиции из корзины (`remove-cart-item.spec.ts`)
   - Добавить товар, открыть корзину, нажать `✕`, убедиться что корзина пуста.

10. ✅ Пересчёт в корзине (`cart-recalculation.spec.ts`)
    - Изменить количество в корзине, итог пересчитывается.

## Низкий приоритет / сложные

11. ✅ Устаревший quote (`quote-expired.spec.ts`)
    - Добавить товар, перейти к оплате, изменить корзину в другой вкладке/через API, нажать "Оплатить".
    - Ожидать сообщение "Расчёт устарел" и кнопку возврата к чекауту.

12. ✅ Восстановление незавершённого платежа после перезагрузки (`payment-recovery.spec.ts`)
    - Начать оплату картой success, до появления успеха обновить страницу.
    - Поллинг должен продолжиться и в итоге показать успех.

13. ✅ Конфликт версий корзины (409)
    - Покрыт в `quote-expired.spec.ts`: изменение корзины через API → «Расчёт устарел».
    - UI обрабатывает и `QUOTE_EXPIRED`, и `CART_VERSION_CONFLICT`.

## Следующий шаг

1. **Итоговая проверка**: запустить все e2e-тесты, убедиться что все 13 сценариев зелёные.
2. **Финальный отчёт**.
